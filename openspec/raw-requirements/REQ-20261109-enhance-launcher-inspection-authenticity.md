## 3. Spec-Kit 三要素展开定义

### 【条目 1】巡检功能精准定位与现状审计 (REQ-INSP-01)
- **场景故事**：用户在快速启动工作台点击“探查”或观察状态呼吸灯，希望确认当前巡检到底在探测什么，为什么某些应用明明开着却显示未运行，或者状态不够真实。
- **功能契约**：
  - 系统 SHALL 明确指出现有巡检模块物理链路：前端 `src/components/LauncherDashboard.tsx`（`pollPorts` 及 4s 定时器）与后端 `src-tauri/src/lib.rs`（`check_service_ports`）；
  - 系统 SHALL 明确揭露 2 大虚假与盲区漏洞：
    1. **桌面应用全盲区**：微信、企微、FlClash、Antigravity、ChatGPT、AI Study 没有任何端口，之前全靠点击开关时的本地伪状态（Optimistic State），外部启闭无法感知；
    2. **端口检测单薄**：只做 TCP 握手，未验证进程是否对应目标服务，无法识别僵尸进程或无效端口。
- **验收指标**：输出巡检代码定位说明与真实性不足根因清单。

### 【条目 2】桌面应用真实进程级存活探测 (REQ-INSP-02)
- **场景故事**：用户在电脑后台开着微信、企微、FlClash 或 Antigravity，打开 SW 工作台，“快速启动”能够立即真实检测到它们已经在运行，呼吸灯自动点亮为翠绿色；用户在任务栏关闭应用后，工作台自动变灰熄灭。
- **功能契约**：
  - 系统 SHALL 支持多进程名称真实扫描（如 `Weixin.exe`/`WeChat.exe`, `WXWork.exe`, `FlClash.exe`, `Antigravity.exe`, `Antigravity IDE.exe`, `ChatGPT.exe`, `cockpit-tools.exe`, `AIstudy.exe`）；
  - 巡检返回各个应用的真实存在状态与主进程 PID；
  - 前端左侧开关与指示灯与真实系统状态严格同步。
- **验收指标**：手动启动/杀死进程，在下次巡检（或点击“探查”）时界面状态真实跳变，准确率 100%。

### 【条目 3】Web 服务与容器双重见证健康探针 (REQ-INSP-03)
- **场景故事**：用户启动了 DeepSeek Harness、MSDS 引擎或 StudyPower，希望确认它们不仅是端口通了，而是服务真的健康响应。
- **功能契约**：
  - 对配置端口的服务（:9010, :3100, :5173, :5174, :18765, :7891, :49374, :9011）：
    1. 执行本地 TCP 端口监听校验；
    2. 支持 HTTP 极速 HEAD/GET 探活（例如 MSDS API `/api/msds/health`）；
    3. 支持进程关键字校验（例如持有端口的是否为期待的服务）。
- **验收指标**：服务启动中到完全就绪各阶段呼吸灯颜色精确无误。

### 【条目 4】统一巡检事实流与控制台联动 (REQ-INSP-04)
- **场景故事**：用户点击“🔍 探查”按钮，右侧控制台不仅是默默刷新，而是打印出当前巡检的真实结果（如检测到多少个进程存活、哪些端口在监听），给用户确定性的安全感。
- **功能契约**：
  - 点击“🔍 探查”时，右侧终端输出：`[INFO] [inspect] 开始全面系统巡检...`；
  - 探查完成后追加结构化诊断小结：`[SUCCESS] [inspect] 巡检完成: 发现 X 个进程运行中，Y 个服务端口活跃...`；
  - 如果发现预期运行但端口未通的服务，输出告警提示。
- **验收指标**：控制台实时呈现清晰、专业的巡检审计报文。

### 【条目 5】高性能低开销与系统不变量 (REQ-INSP-05)
- **场景故事**：巡检每 3~5 秒自动在后台运行，不能出现界面卡顿、丢帧或 CPU 飙升。
- **功能契约**：
  - 进程与端口探测采用并发机制，整体执行时间控制在 200ms 以内；
  - 保持黑灰白极简亚克力设计、自定义背景设置、44px 平齐水平线等既有不变量 100% 不退化。
- **验收指标**：编译与静态检查 0 错误 0 警告，离线单文件 EXE 运行顺畅。
