# Specification: 纯净分区架构、子分区治理与笔记数据库行为契约

## 1. 虚假元素清除契约 (Zero Mock Policy)
- **SHALL**: 系统界面上绝对禁止出现任何无法交互、无对应数据表支撑的占位文本或装饰性假按钮。
- **SHALL**: 必须彻底移除侧栏顶部“主页”、“新对话”、“外部代理”三大项，顶栏“共享”、“复制链接”、“上次编辑 刚刚”等假按钮，以及硬编码的“Jr Forever 的工作空间 总部”。

## 2. 三大法定根模块契约 (Root Sections Contract)
- **SHALL**: 侧栏顶级仅保留三个法定总模块：`private`（私人）、`recent`（最近）、`favorite`（收藏）。
- **WHEN**: 用户点击任意一个总模块的折叠箭头时，
- **THEN**: 该模块内容必须在 120ms 内完成平滑折叠/展开，并持久化折叠状态。
- **WHEN**: 用户在任意笔记或数据库上点击星标 ⭐ 时，
- **THEN**: 该条目必须无延迟同步在【收藏】模块中出现或移除。
- **WHEN**: 用户编辑修改了某篇笔记或数据库内容时，
- **THEN**: 该条目在【最近】模块中必须自动升序置顶显示。

## 3. 私人模块子分区管理契约 (Sub-Partition Governance)
- **SHALL**: 【私人】模块支持无限层级或多级子分区（分类文件夹）管理。
- **WHEN**: 用户在【私人】头部或子分区行右侧点击「+ 新建子分区」时，
- **THEN**: 系统必须生成一个新的 `DocPartition` 记录，其 `parentId` 指向该父分区，并允许用户内联修改子分区名称。
- **WHEN**: 用户删除某个子分区时，
- **THEN**: 系统必须安全级联删除该子分区及其下属包含的未移交笔记与数据库，并同步从 SQLite 中清除。

## 4. 笔记数据库与独立笔记创建契约 (Database & Note Contract)
- **WHEN**: 用户在某个子分区或私人根目录下点击「+ 新建数据库」时，
- **THEN**: 系统必须新建一个 `DbCollection`，其 `partitionId` 严格绑定到当前子分区，该数据库内初始包含表头，用户可自由向其中添加多篇笔记（每一行即是一篇带属性的独立笔记）。
- **WHEN**: 用户在某个子分区或私人根目录下点击「+ 新建笔记」时，
- **THEN**: 系统必须新建一个单篇 `DocPage`，其 `partitionId` 严格绑定到当前子分区，右侧直接载入块级正文编辑器供用户随心书写。
