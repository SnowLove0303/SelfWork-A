# Proposal: Local Embedded SQLite Database Persistence

## 1. Context & Motivation
用户提出核心数据可靠性诉求：
「要接数据库保留用户操作，避免 重启后 之前的操作数据丢失」。

目前系统部分数据依赖前端浏览器环境的 `localStorage`。虽然在一般情况下可用，但在遇到操作系统垃圾清理、WebView2 临时缓存被重置或升级时，存在数据丢失的偶发风险，且缺乏真实的 ACID 事务保障。

本提案确立将工业级嵌入式 **SQLite 微内核** 原生集成进 Tauri 后端（`rusqlite` bundled 静态编译）：
1. **物理数据库落盘**：在本地用户数据目录安全创建 `selfwork.db`，具备 WAL 预写日志与事务完整性，避免断电/强退文件损坏；
2. **全量核心业务数据入库**：为待办事项 (`tasks`)、灵感便签 (`memos`)、外观设置 (`app_settings`) 建立结构化表；
3. **老用户历史数据无感平滑迁移**：启动时自动侦测既有 `localStorage` 数据并无缝导入 SQLite，杜绝升级丢失；
4. **绿色单文件守恒**：SQLite 静态编译嵌入单一 `SelfWork.exe`，无需安装任何外部数据库服务，拷贝即用。

## 2. 1:1 需求物理对账矩阵 (Spec-Kit RTM)

| 需求编号 | 需求事实与目标定位 | 对应 Spec-Kit 核心要求 | 物理验收充要指标 [Measured] |
| :--- | :--- | :--- | :--- |
| **REQ-DB-01** | **嵌入式本地数据库接入与安全落盘** | 引入零配置、极速嵌入式 SQLite 数据库，建立物理数据库文件持久化（`selfwork.db`），启动自动检查建表与版本迁移，彻底摆脱易被清理的临时浏览器缓存 | 本地生成物理 `.db` 数据库文件，ACID 事务保障，异常断电/强退/重启数据 100% 完好不损毁 |
| **REQ-DB-02** | **待办清单 (Tasks) 全生命周期数据库管理** | 建立 `tasks` 权威数据表，支持任务创建、状态流转（待办/进行中/已完成）、优先级更新、物理删除与一键清理的真实 SQL 读写 | 任何待办增删改即刻写入数据库，重新打开应用 100% 还原全部任务与完成状态 |
| **REQ-DB-03** | **灵感便签 (Sticky Memos) 实时持久化入库** | 建立 `memos` 权威数据表，支持便签卡片新增、标题与正文就地编辑、置顶（Pin）、主题冷色调与删除的真实 SQL 读写 | 编辑便签失去焦点即自动同步入库，置顶排头顺序与卡片色调在重启后完全保持 |
| **REQ-DB-04** | **外观配置持久化与既有数据无缝平滑迁移** | 建立 `settings` 表存储外观、壁纸与高精透明度配置；首次启动自动读取既有历史配置并无缝平滑迁入数据库 | 老用户已有壁纸设置、已有待办与便签零丢失，平滑无感升级 |
| **REQ-DB-05** | **单文件免安装 EXE 绿色特性与零配置守恒** | 嵌入式数据库微内核静态编译内嵌进 `SelfWork.exe`，无需用户安装任何外部数据库服务（如 MySQL/PostgreSQL），拷贝即用 | `cargo test` 退出码 0，全量打包单文件 EXE 退出码 0，离线独立运行秒开 |
