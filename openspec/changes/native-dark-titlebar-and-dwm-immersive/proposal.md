# OpenSpec Change Proposal: native-dark-titlebar-and-dwm-immersive

## 1. 需求背景与方案选型 (Problem & Decision)
在之前的无边框窗口改造中，由于 Webview2 内部软件模拟拖拽存在事件捕获、异步通信及缺乏系统级硬件加速的问题，用户反馈体验与原生窗口拖动存在差距，明确要求：**“还是不能自然移动啊，我想要原始窗口那种拖拽移动方式”**。

经方案比选与用户明确定向确认，本变更采用 **“恢复 Windows 原生系统标题栏 + 启用 DWM 沉浸式深色模式（DWMWA_USE_IMMERSIVE_DARK_MODE）”** 方案：
1. 恢复 Windows 原生系统标题栏，使窗口拖拽、Aero Snap（分屏贴靠）、Snap Layouts 与多显示器流转完全交由 Windows 操作系统硬件内核驱动，达到 100% 原始窗口拖拽流畅度；
2. 在 Rust 微内核与配置中注入 Windows DWM 沉浸式暗黑模式属性（DWMWA 20/19 与 theme: Dark），将原生标题栏由刺眼的浅白灰强行刷为深邃的暗黑色，彻底根除深浅视觉割裂；
3. 清理前端 `Header` 中冗余的自定义最小化/最大化/关闭按钮与模拟拖拽代码，恢复纯净精致的工作台顶栏布局。

## 2. 1:1 Spec-Kit 需求物理对账矩阵 (RTM Matrix)

| 需求编号 | 需求归纳 | 核心场景诉求 | 验收度量准则 (Acceptance Criteria) |
| :--- | :--- | :--- | :--- |
| **REQ-NATIVE-1** | **恢复 Windows 原生标题栏与 100% 原生系统级拖拽** | 彻底回归操作系统原生窗口机制，消除任何前端模拟拖拽带来的卡顿、断触或不自然感，重现原生流畅物理移动。 | 1. 窗口具备标准的 Windows 原生标题栏。<br>2. 鼠标按住标题栏拖动，100% 拥有 Windows 原生硬件级响应速度、平滑度与惯性物理。<br>3. 完美支持 Windows 10/11 的 Aero Snap（拖至屏幕边缘自动半屏/四分屏）、Snap Layouts 贴靠菜单以及双击最大化/还原。 |
| **REQ-NATIVE-2** | **启用 DWM 沉浸式深色模式，根除浅灰白割裂** | 解决最初导致视觉断层的核心痛点：消除浅灰白色原生外壳，使系统标题栏与暗黑科技风工作台浑然一体。 | 1. Windows 原生标题栏背景自动呈现为沉浸式深色/纯黑，不再呈现刺眼的浅灰白色。<br>2. 标题栏文字呈现清晰的反白/浅灰，标题栏自带的系统级最小化、最大化、关闭按钮呈现暗黑原生微交互。<br>3. 整个应用从顶栏到主画板呈现协调统一的暗色调。 |
| **REQ-NATIVE-3** | **顶栏去重与纯净布局恢复** | 原生标题栏回归后，顶栏不应与系统标题栏产生功能重叠或“双重按钮”视觉冗余。 | 1. 移除前端页面右上角自定义的最小化、最大化、关闭按钮，避免出现“上下两套控制按钮”的混乱。<br>2. 移除前端冗余的模拟拖拽事件监听代码。<br>3. 现有顶栏专注于模块导航（当前模块名、副标）与内核状态胶囊，布局精致精炼。 |
| **REQ-NATIVE-4** | **业务逻辑保持现状与质量门禁不变量** | 外壳机制调整不得干扰现有核心业务功能与底座质量。 | 1. 快速启动器（进程扫描/启停/日志）、待办清单与便签墙（SQLite 物理落盘）逻辑 100% 保持现状。<br>2. 编译 zero warnings, zero errors，底层测试 100% 通过，更新单文件便携可执行程序交付。 |
