# Proposal: Docs Table Self-Healing, Notion Flat Summary Purge, and Legacy Page Data Healing

## 1. 提案背景与问题陈述 (Context & Problem Statement)

用户在打开《02.3-02.5 集合类型、映射类型与其他内置类型》文档时，截图标注了两个严重破坏阅读与排版体验的故障区段：
1. **代码块与表格之间的噪点段落（红框 1）**：
   出现一整行冗长且字段重复的文本：
   `| 运算 Python 写法 结果 并集 A \| B {1, 2, 3, 4, 5} 交集 A & B {3} 差集 A - B {1, 2} 对称差集 A ^ B {1, 2, 4, 5} | 运算 | 运算 | Python 写法 | Python 写法 | 结果 | 结果 | 并集 | 并集 | A \| B | A \| B | {1, 2, 3, 4, 5} | ... |`
2. **紧随其后的表格块（红框 2）**：
   呈现为畸变的 6 列 × 5 行结构，表头被双倍克隆（`运算` | `运算` | `Python 写法` | `Python 写法` | `结果` | `结果`），且第一行数据 `A \| B` 内的转义竖线被分裂切碎为 `A \` 和 `B`。

经过 **5-Whys 深度根因穿透**，查明物理事实：
- 该页面记录是在 **2026-11-18**（两天前）最初写入 SQLite 数据库的；
- `v0.1.74` 修复的净化器仅作用于**新文件导入/新文本粘贴**，并未对数据库中的存量历史页面进行向后兼容的物理清洗与自愈；
- 系统缺乏**“运行时加载自愈护盾”**：当编辑器加载到历史破损表格或其上方的 Notion 扁平汇总噪点段落时，没有自动规整与过滤，直接原样暴露给用户。

## 3. 架构影响与风险评估 (Impact Analysis)

1. **对数据库的安全性**：
   - 采用事务级原子操作与字段值级规整，仅针对确认破损的噪点段落与克隆表格做精准修复，绝对不触碰其他正常 blocks；
2. **对已有功能的不变量承诺**：
   - 表格自由拖拽调整列宽机制 100% 保持稳定；
   - 字符级选区、大纲折叠、Tauri 本地落盘 100% 保持稳定。
