# Proposal: Enhance Quick Launcher Inspection Authenticity

## 1. Context & Motivation
在快速启动工作台首发上线后，用户明确提出核心优化诉求：**「找到巡检功能，强化巡检检测的真实性」**。
经代码拓扑审计发现，当前巡检体系存在严重真实性缺陷：
1. **常用桌面软件全盲区**：微信、企业微信、FlClash、Antigravity、ChatGPT、AI Study 等由于没有固定监听端口，当前巡检逻辑根本未对其进行检测，全凭点击开关时的本地假状态（Optimistic State）；外部启闭无法感知；
2. **端口检测单薄**：仅进行裸 TCP 握手，无法区分目标服务与随机占用的无关程序，未关联进程树；
3. **缺少真实诊断日志**：点击“探查”或后台轮询时静默无回显，未向执行报文控制台输出真实的诊断事实证据。

本项目旨在通过 Rust 微内核原生集成 Windows 进程快照扫描、TCP/HTTP 双重见证探针及结构化巡检诊断事实流，彻底根除“假通/伪状态”，将巡检提升为座舱级真实系统诊断。

## 2. 1:1 需求物理对账矩阵 (Spec-Kit RTM)

| 需求编号 | 需求事实与目标定位 | 对应 Spec-Kit 核心要求 | 物理验收充要指标 [Measured] |
| :--- | :--- | :--- | :--- |
| **REQ-INSP-01** | **巡检功能精准定位与弱点审计** | 精准定位现有巡检代码逻辑位置，穿透分析当前真实性不足的核心原因（仅测 TCP 端口、非端口应用 100% 盲区依赖点击伪状态、未测真实进程树与健康探针） | 输出完整的巡检现状定位报告与漏洞因果拓扑图 |
| **REQ-INSP-02** | **桌面应用真实进程级存活穿透探测** | 全面覆盖常用办公与 AI 套件（微信、企微、FlClash、Antigravity、Antigravity IDE、ChatGPT、Cockpit、AIstudy 等）的真实进程运行感知 | 无论在工作台内启动还是外部手动打开/关闭，巡检均能 100% 真实感知并实时同步开关与呼吸指示灯 |
| **REQ-INSP-03** | **Web 服务与容器双重见证健康探针** | 核心 Web 平台与服务（DSH、StudyPower、MSDS、冠志通 Docker、飞书桥接）在端口探测基础上强化真实性校验（进程关联/HTTP健康探针） | 排除随机无效端口占用欺诈，真实反映后台 Web/API 服务就绪状态 |
| **REQ-INSP-04** | **统一巡检事实流与诊断报文回显** | 建立全维真实巡检数据契约，点击“🔍 探查”或巡检探测出状态变化时，在右侧报文终端输出真实的巡检诊断报文（PID、端口、容器） | 控制台有据可查，输出包含真实活跃进程数与端口详情的结构化报文 |
| **REQ-INSP-05** | **高频巡检低开销与系统不变量守恒** | 探测逻辑毫秒级多线程并发（$\le 200\text{ms}$），不占 CPU，UI 零卡顿；保持既有外观设置、黑灰白磨砂玻璃、44px 水平线与单文件 EXE 离线秒开 | 静态类型检查零错误、单元测试通过、全量打包退出码 0，离线运行丝滑 |
