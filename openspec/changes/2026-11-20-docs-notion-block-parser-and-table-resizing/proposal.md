# 变更提案：文档模块识别补强、导入噪点清洗、表格自由拖拽与 Notion 规范对齐

## 变更背景与需求来源
用户在日常深度使用 SelfWork 文档模块过程中，导入/粘贴外部 Notion 网页或复杂结构文档时暴露了多项严重破坏排版与交互体验的缺陷：
1. **导入与解析存在大量 UI 噪音残留**：混入 Notion 平台顶栏外壳信息（`废纸篓私人 / 02.3-02.5...`、`·1399 个块`、`目录大纲(190)`、`添加封面` 等），代码块中被混入操作按钮文字与行号（`Python不换行行号复制123456`），表格上方混入 SelfWork 或 Notion 的工具栏文本（`数据表格2 列 × 5 行首行表头复制 MD加列加行...`）；
2. **表格结构严重畸变与重复列名克隆**：由于朴素的 `.split('|')` 切分误伤单元格内转义竖线 `\|`，导致表格列被错误切割爆炸，表头被重复拼接为 `| 运算 Python 写法 结果 ... | 运算 | 运算 | Python 写法 | Python 写法 | ... |` 的严重畸变结构；
3. **表格交互能力严重缺失——无法横竖拉动**：表格各列无法像 Notion/Excel 那样自由左右拖拽调整宽度，多列长表无法平滑水平滚动与横向拖动；
4. **对齐 Notion 规范与识别思路**：对标 Notion 官方规范（参考 `https://app.notion.com/p/02-3-02-5-40d003b68bec801b9151f90453602823`），深入贯彻块级别（Block-level）语义抽象、内容事实与 UI 外壳解耦原则。

---

## 1:1 需求物理对账矩阵 (Requirements Traceability Matrix - RTM)

| 需求 ID | 用户原始诉求与核心要点 | 拟定技术实现方案 | 验收标准 (Acceptance Criteria) |
|---|---|---|---|
| **REQ-DOC-PARSE.1** | 文档导入/粘贴清洗：剔除面包屑 `废纸篓私人 / ...`、大纲统计 `·1399 个块目录大纲(190)`、封面按钮 `🐍🖼️添加封面` | 在 `markdownImport.ts` 及粘贴管道中增加 `sanitizeImportText`，自动剥离 Notion 顶栏、元数据及操作提示文本 | 导入用户样本时，页面标题精准提取为 `02.3-02.5 集合类型、映射类型与其他内置类型`，图标提取为 `🐍`，正文开头纯净呈现 `📌本节定位...`，零外壳噪点 |
| **REQ-DOC-PARSE.2** | 代码块清洗：消除 `Python不换行行号复制123456# ...` 与输出中的复制/行号残屑 | 在导入流与代码块匹配逻辑中，识别并剔除语言切换、不换行/换行开关、行号开关、复制按钮及连续行号伪文本，还原纯净语言标签与代码内容 | 代码块语言识别为 `python`，首行纯净呈现 `# 创建一个列表，保存收到的用户名`，输出区代码纯净还原，零按钮行号噪点 |
| **REQ-DOC-PARSE.3** | 表格解析去重与防畸变：修复转义竖线 `\|` 导致的行列爆炸与重复列名克隆 | 重构表格切分逻辑，采用负向后行断言 `/(?<!\\)\|/` 识别真实列分隔符，反转义保护单元格内容，增加行列规整与重复表头去重 | 解析包含 `并集 A \| B` 等转义竖线的表格时，列数严格与表头对齐，杜绝重复列名与多重表头克隆 |
| **REQ-TABLE-INTERACT.4** | 表格自由拖拽调整列宽与横向平滑滚动 | 在 `TableBlock.tsx` 中增加 `columnWidths: number[]` 状态并持久化至 `properties`；表头右侧渲染 `col-resize` 拖拽手柄；容器采用 `overflow-x-auto custom-scrollbar`，支持平滑横向拖拽查阅 | 用户可将鼠标悬停在表头右侧边缘左右拖拽修改列宽，多列时表格自适应横向平滑滚动，交互流畅无卡顿 |
| **REQ-NOTION-ALIGN.5** | 编辑器智能粘贴与 Notion Block 对齐 | 在 `BlockItem.tsx` / `BlockEditor.tsx` 中建立结构化粘贴接管：粘贴多行 Markdown/网页文本时自动通过清洗管道解析并无缝分裂插入为独立 DocBlocks | 在任意段落中粘贴多段落/代码块/表格 Markdown 内容时，系统自动切分为对应块结构，不出现单块内挤压塞满现象 |
