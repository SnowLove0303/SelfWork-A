# Specification: Notion 风格分区、行即页面与 Side Peek 行为契约

## 1. 分区层级治理行为契约 (Partition Governance)
- **SHALL**: 系统必须提供独立的分区概念（`DocPartition`），默认预置 `private`（私人）、`favorite`（最爱）、`workspace`（团队/项目区）。
- **WHEN**: 用户点击某个分区的折叠箭头时，
- **THEN**: 该分区下的所有页面与数据库列表必须在 120ms 内平滑折叠/展开，并持久化折叠状态。
- **WHEN**: 用户在某个分区头部点击 `+` 按钮时，
- **THEN**: 系统必须在该分区根节点下创建新的文档页面或多维表格，且 `partitionId` 必须严格绑定到该分区。

## 2. 行即页面 (Row-as-Page) 与双向多维属性契约
- **SHALL**: 数据库中的每一行数据（`DbCollectionRow`）必须对应一个真实的文档页面记录（`DocPage`）。
- **WHEN**: 用户在数据表格中修改某个单元格的值时，
- **THEN**: 物理库必须同步更新该行记录的 `cells_json`，若打开了该行的 Side Peek 抽屉，其顶部对应的属性输入框必须无延迟同步反映新值。
- **WHEN**: 用户在 Side Peek 抽屉顶部的属性卡片中修改某个字段（如优先级、状态胶囊、日期）时，
- **THEN**: 左侧数据表中的对应单元格必须实时双向同步刷新，并持久化到 SQLite 物理库。

## 3. Side Peek 侧边预览抽屉行为契约
- **SHALL**: 数据表格每一行最左侧的标题单元格悬浮或点击时，必须提供「打开 / 预览」交互手柄。
- **WHEN**: 用户点击该手柄或点击行内标题时，
- **THEN**: 系统必须以双栏分栏形式在右侧滑出 Side Peek 抽屉（宽度占比 50%~60%），左侧表格自适应收缩为精简浏览模式。
- **SHALL**: Side Peek 抽屉内必须包含：
  1. 顶部操作栏（最大化为全屏页面、关闭抽屉、删除页面）；
  2. 页面图标与大标题编辑框；
  3. 属性面板（渲染当前数据库中定义的全部字段，可直接点选修改）；
  4. 正文富文本块编辑器（包含段落、H1/H2/H3、待办、列表、代码块与 `/` 斜杠指令）；
  5. 在页面正文内支持通过 `/table` 嵌入下级子数据库。

## 4. 多视图 Tab 栏行为契约
- **SHALL**: 数据库顶部必须提供视图 Tab 栏（如 `⊞ 全景调研表`、`⊞ 进行中任务` 等），支持切换不同视图配置。
- **WHEN**: 用户点击右上角蓝色「+ 新建 ⌄」主按钮时，
- **THEN**: 系统必须在当前视图末尾立即新建一行记录，并在右侧直接滑出该新建行的 Side Peek 抽屉供用户沉浸式录入。
