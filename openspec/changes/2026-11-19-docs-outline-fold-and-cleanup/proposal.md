# 变更提案：文档大纲展开按钮收敛与父子级标题折叠系统 (Proposal)

## 一、 需求溯源与问题背景

在大型文档编辑与长文导航场景中，用户反馈了两个关于目录大纲的核心可用性与空间问题：
1. **展开入口重复冗余**：顶栏右侧已常驻「目录大纲」按钮，而正文编辑区右侧边缘又悬浮了一个「大纲」指示胶囊，双入口并存造成界面混乱；
2. **大纲缺乏父子层级折叠**：百级大纲（如包含 190+ 个标题的长篇手册）目前为平铺展示，无法按主干章节折叠/展开，视窗极其冗长，翻找检索效率低下。

## 二、 1:1 需求物理对账矩阵 (RTM 继承)

| 需求编号 | 需求名称 | 契约重点 |
| :--- | :--- | :--- |
| **REQ-TOC.1** | **收拢展开入口：移除编辑区下方重复的目录展开按钮** | 彻底移除编辑区右侧悬浮常驻的大纲胶囊按钮，保留顶栏右侧按钮作为大纲收展的唯一权威控制入口。 |
| **REQ-TOC.2** | **开发目录父子级标题折叠与展开功能** | 建立 H1 > H2 > H3 树形管辖关系，为有子标题的父节点提供独立的折叠/展开箭头，支持按章节折叠隐藏子项，文本点击与折叠点击物理隔离，兼容现有层级筛选器。 |

## 三、 拟变范围与影响半径

- 变更文件严格限制在 `src/components/docs/editor/BlockEditor.tsx`。
- 其他组件（`BlockItem.tsx`、`DocsView.tsx`、数据库存储层等）绝对保持只读与现状。
