# 变更提案：文档字符级高精选区与零延迟即划即现引擎重塑 (Proposal)

## 一、 需求背景与动机
用户在实际体验中连续指出两个关键缺陷：
1. **粒度粗糙**：“现在跨行选中，哪怕选到第二行的一个字，都是整行整块选中，不太自然，你可能没理解类似于word的选中那般自然是什么意思”；
2. **性能迟滞**：“执行，且选中过程中的延迟等要低到足够自然，不然我在前边选中，选中时的反应却在后面追，感觉很卡啊”。

分析根因：之前采用 React 顶层 `crossSelectedBlockIds` 状态机在全局 `mousemove` 中高频调用 `setCrossSelectedBlockIds`，触发 React 组件树全量重复渲染，不仅使高亮以“块”为单位粗暴涂抹整段，更造成严重的调度队列堆积与丢帧迟滞，导致“鼠标跑在前，高亮在后追”。

本提案旨在引入现代 W3C 标准 **CSS Custom Highlight API (`CSS.highlights`)** 结合 DOM Range 原生驱动机制：
- 彻底跳过 React 状态调度，实现 120Hz/144Hz 硬件加速即划即现，消除所有延迟与卡顿；
- 实现字符级（Character-level）精确起止，鼠标划入第 1 个字就严格只高亮第 1 个字，前面的字与后面的字完全保持原样，还原 Office Word 般纯粹自然的手感与剪贴板所见即所得。

## 二、 1:1 Spec-Kit 需求对账矩阵 (RTM)

| 需求条目序号 | 原始意图指纹 | 对应规格契约 | 验收判定依据 |
| :--- | :--- | :--- | :--- |
| **REQ-WORD-SELECT.1** | 终结整行涂抹，实现尾段字符级精准停靠 | 划选进入目标段落时，通过 `caretRangeFromPoint` 锁定具体字符，仅高亮段首至当前字符，后部保持原状 | 鼠标划入第二行第 1 个字时，仅第 1 个字高亮，第二行后续文字无色 |
| **REQ-WORD-SELECT.2** | 首段起始字符精确起跑，排除落点前文本 | 划选启动时记录鼠标落点文本字符位置，落点前面的文字完全不选中，仅落点至段末高亮 | 从段落中间某个词拖拽时，该词前面的全部文字保持未选中外观 |
| **REQ-WORD-SELECT.3** | 零延迟即划即现，彻底消除“反应在后面追” | 剥离 `mousemove` 中的频繁 React `setState`，采用 CSS Highlight / Range 底层直接渲染 | 鼠标在屏幕上快速滑动，高亮瞬时跟随，零丢帧、零拖尾、不卡顿 |
| **REQ-WORD-SELECT.4** | 双向自由流式拖选与中间段平滑衔接 | 支持从上到下、从下到上双向拖拽，中间穿透段落全文高亮，首尾段字符级精准截断 | 反向拖拽平滑跟随，中间段落自然衔接，单段与跨段无缝过渡 |
| **REQ-WORD-SELECT.5** | 剪贴板复制所见即所得 (WYSIWYG Clipboard) | `Ctrl+C` 提取实际高亮的精确字符流与换行写入剪贴板；`Backspace` 精准删除 | 复制内容严格等于屏幕高亮文字，无前后未选文字溢出 |
