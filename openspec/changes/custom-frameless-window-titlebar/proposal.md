# OpenSpec Change Proposal: custom-frameless-window-titlebar

## 1. 需求背景与问题定义 (Problem Statement)
目前应用顶部使用 Windows 原生标题栏，呈现浅灰白色背景，包含 SW 图标、SW工作台文字以及最小化、最大化、关闭按钮。但应用主体采用深色科技风 UI，导致原生标题栏与主界面之间出现明显的视觉割裂，破坏了整体设计一致性与沉浸感。

本变更将桌面应用升级为**无边框窗口 (Frameless Window) + 自定义标题栏 (Custom Titlebar)**，将窗口控制功能与原生交互自然整合进现有顶部导航区域，而不额外增加一层标题栏，消除视觉割裂，实现浑然一体的现代桌面工作台质感。

## 2. 1:1 Spec-Kit 需求物理对账矩阵 (RTM Matrix)

| 需求编号 | 需求归纳 | 核心场景诉求 | 验收度量准则 (Acceptance Criteria) |
| :--- | :--- | :--- | :--- |
| **REQ-1** | **统一视觉风格与消除浅色原生标题栏** | 消除 Windows 原生白灰标题栏导致的视觉断层，窗口顶端至内容区呈现浑然一体的深色暗夜质感。 | 1. 窗口无白色/浅灰色原生标题栏条。<br>2. 顶栏背景色与现有主界面亚克力磨砂及深色调浑然天成，无割裂线。<br>3. 无过度装饰，恪守极简科技风。 |
| **REQ-2** | **顶部导航一体化整合与空间利用最大化** | 避免在现有导航栏上方强行“叠床架屋”多加一层标题栏；将窗口控制功能与拖曳功能深度嵌入现有顶部区域。 | 1. 垂直高度不额外增加一层专用标题条，最大化保留有效工作区高度。<br>2. 侧栏 Brand（Logo + SW工作台）与顶栏标题（页面名/状态）空间布局无缝咬合，不重复出现 SW Logo 与应用名。<br>3. 各元素层次清晰，桌面原生质感显著。 |
| **REQ-3** | **自定义窗口控制按钮（最小化、最大化/还原、关闭）** | 在右上角建立符合桌面人机工程学的窗口三按键，提供精确的视觉反馈与克制交互。 | 1. 右上角集成最小化（`-`）、最大化/还原（`□` / `❐` 状态自适应联动）、关闭（`✕`）三组细线条按键。<br>2. 默认保持低对比度柔和浅灰；悬停有微反光背景；关闭按钮悬停呈现克制柔和暗红反馈。<br>3. 点击热区与按键尺寸符合 Windows 桌面操作直觉。 |
| **REQ-4** | **保全完整的 Windows 原生窗口交互与边界体验** | 无边框改造后，不能损失窗口最基础的桌面操作能力。 | 1. 顶栏非交互空白区域支持鼠标长按拖拽移动窗口。<br>2. 双击顶栏空白区域能够即时触发窗口最大化与还原切换。<br>3. 窗口四周边缘仍能顺畅吸附并拖拽缩放尺寸（Resize）。<br>4. 最大化时窗口铺满屏幕但不溢出、不遮挡任务栏、不裁切边缘。<br>5. 拖拽热区物理隔离：拖拽区域绝对不覆盖左侧展开按钮、模块标题、状态胶囊与窗口控制按钮自身，防止点击被系统吞没。 |
| **REQ-5** | **标准框架机制与既有业务逻辑隔离不变量** | 依托框架原生支持的无边框与窗口控制通道，保护既有核心业务代码现状。 | 1. 使用桌面框架官方支持的标准窗口无装饰模式与控制 API，杜绝脆弱黑客注入。<br>2. 严格保留现有快速启动（进程探针/启停/日志）、待办清单/便签（SQLite 持久化）以及响应式自适应布局现状。<br>3. 编译 zero warnings, zero errors，单文件 release 生产可执行程序完整交付。 |
