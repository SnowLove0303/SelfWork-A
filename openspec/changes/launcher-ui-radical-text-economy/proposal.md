# Proposal: Launcher UI Radical Text Economy and Anti-AI-Slop Refactoring

## 1. Context & Motivation
在快速启动仪表盘与全维巡检上线后，用户明确指出 UI 界面开发原则问题：
「UI需要调整一下，还记得 UI界面的开发原则吗，比如说 flaclash，有 名字的情况下，就不要再加一段说明了，显得很多余」。

经对照系统最高设计准则 `ui-ux-design-engineering`，现有界面违反了 **少字原则与极简微文案公理 (`RADICAL_TEXT_ECONOMY_AXIOM`)** 与 **业务卡片零废话公理 (Zero-Prose in Operational Cards)**：
1. **废话解释泛滥**：卡片中嵌入了“多协议高性能网络代理客户端”、“腾讯微信 Windows 官方桌面版”等显而易见、自明多余的静态副标题段落；
2. **垂直几何冗余**：常驻说明文本导致卡片高度被撑大到 60px+，造成大量无意义留白，首屏可视服务数量被腰斩；
3. **集群标题多余**：集群标头常驻“日常办公沟通、网络代理与自动化签到”等通用套话，产生视觉噪音。

本变更将彻底清除卡片与标头中的冗余文本段落，将条目精炼为紧凑的单行水平平齐结构（40~44px 高度），辅助说明降级为原生 Tooltip 悬停气泡，将空间与首屏视觉让位给核心状态与控制入口，重塑一流的工业座舱质感。

## 2. 1:1 需求物理对账矩阵 (Spec-Kit RTM)

| 需求编号 | 需求事实与目标定位 | 对应 Spec-Kit 核心要求 | 物理验收充要指标 [Measured] |
| :--- | :--- | :--- | :--- |
| **REQ-UI-01** | **落实少字原则 (Radical Text Economy) 根除冗余说明** | 彻底移除操作卡片内部默认常驻渲染的次级说明文本段落（如 FlClash、微信、企微、ChatGPT 等软件下方的解释性废话）；若确有底层技术参数，仅通过原生悬停 Tooltip 呈现 | 卡片条目内常驻说明文字 100% 清零，杜绝一切 AI 模版式套话 |
| **REQ-UI-02** | **精炼卡片几何结构与提升座舱信息密度** | 重构左侧卡片条目为工业级单行水平平齐咬合：【精致图标】+【服务名称】+【端口/PID 胶囊】+【状态指示灯】+【触觉开关】，高度收敛至 40~44px | 彻底消除垂直多余间隙，首屏可视服务数量翻倍，手感紧凑高级 |
| **REQ-UI-03** | **集群标题栏文本极简化** | 集群标头同样剔除多余的副标题套话（如“日常办公沟通、网络代理与自动化签到”），仅保留分类名称与一键总控入口 | 分类标头纯净利落，视觉噪音归零 |
| **REQ-UI-04** | **既有系统功能与交互不变量守恒** | 保持真实 Windows 进程快照扫描、真实 PID 徽章、端口跳转胶囊、执行报文控制台联动及启停控制 100% 完好 | 全量编译构建退出码 0，离线运行无故障 |
