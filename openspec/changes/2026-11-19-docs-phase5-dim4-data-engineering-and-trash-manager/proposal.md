# Proposal: 阶段五（维度 4）数据工程与全库深度管理 (P2 资产治理与生命周期闭环)

## 1. 摘要与背景
在阶段五（维度 1 至维度 3）相继交付了知识双向拓扑（v0.1.62）、结构化排版与高级块（v0.1.63）以及行内微交互与极客体验（v0.1.64）后，SelfWork 文档中心的核心编辑、渲染与阅读链路已全面达到生产级体验。
随着用户在日常工作与技术沉淀中创建的文档和多维块越来越多，单篇文档的孤岛管理已无法满足高阶资产治理诉求。
用户急需：
1. 毫秒级跨越全库所有文档块的全局模糊检索引擎，实现“想查即达”；
2. 误删保护与软删除恢复机（废纸篓体系），杜绝物理误删灾难；
3. 侧边栏批量选择与批量转移、软删除、导出管理能力；
4. 外部批量 Markdown 文件一次性解析与结构化入库还原能力。

本阶段（维度 4）是阶段五长程路线的收官之作，将全方位筑牢 SelfWork 文档中心的数据工程基座与资产治理生命周期闭环。

## 2. 1:1 需求物理对账矩阵 (RTM 守恒)
| 需求编号 | 需求名称 | 对应痛点与业务目标 | 场景故事与契约 | 独立验收标准 |
|---|---|---|---|---|
| **REQ-D4.1** | 全库块级全局模糊检索引擎 (`Ctrl+Shift+F` / `DocGlobalSearchModal`) | 现有文档检索仅局限于标题或当前页，无法跨越几百篇文档秒级查找某行代码或表格。 | 全局快捷键 `Ctrl+Shift+F` 唤出 Spotlight 风格居中搜索浮窗，实时扫描全库块内容，支持类型过滤、上下键选中与穿透直达。 | 1. `Ctrl+Shift+F` 即时弹出全局搜索弹窗；<br>2. 跨全库文档扫描内容并高亮关键词；<br>3. 支持按代码/表格/待办/段落过滤；<br>4. Enter 键平滑穿透至目标文档与目标块。 |
| **REQ-D4.2** | 文档废纸篓与软删除恢复机 (`DocTrashDrawer` & `docTrash.ts`) | 现有文档一旦点击删除即直接物理抹除，误操作无挽回途径，存在极大资产丢失风险。 | 删除页面时转为软删除至废纸篓，侧边栏底部提供常驻入口，展示 30 天保留倒计时、一键原位还原与二次确认彻底粉碎。 | 1. 删除文档后在正常列表隐藏并进入废纸篓；<br>2. 点击一键还原完好放回原分区；<br>3. 彻底粉碎前提供二次确认阻断；<br>4. 支持一键彻底清空废纸篓。 |
| **REQ-D4.3** | 文档侧栏多选批量管理 (`DocBatchManager`) | 整理海量旧文档时必须逐篇移动或删除，耗时费力。 | 侧边栏支持多选模式切换，底部/顶部滑出多选浮动手柄，支持批量移动分区、批量移入废纸篓、批量导出 Markdown 与批量收藏。 | 1. 开启多选后复选框清晰呈现；<br>2. 批量移动分区一次性生效并持久化；<br>3. 批量移入废纸篓安全生效；<br>4. 批量导出 Markdown 产出结构化文本。 |
| **REQ-D4.4** | 外部 Markdown 批量导入还原器 (`DocBatchImporter` & `markdownImport.ts`) | 从 Obsidian/Notion 迁入资料需手动一篇篇复制粘贴排版，成本极高。 | 支持一次性选取多份本地 `.md` 文件，解析标题、段落、列表、代码、引用、表格并自动转为 SelfWork 结构化块并入库。 | 1. 支持多选本地 `.md` 文件；<br>2. 标题/代码/待办/表格高保真解析还原；<br>3. 自动生成对应页面并刷新侧边栏；<br>4. 数据原子持久化无丢失。 |
