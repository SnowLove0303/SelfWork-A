# 变更提案：大纲面板收起按钮彻底清除与智能多层级父子折叠系统 (Proposal)

## 一、 需求溯源与问题根因

用户在实际体验 v0.1.67 版本后提出了两项深刻质疑与改进要求：
1. **大纲栏内部右上角多余收起按钮仍存在**：
   - 顶栏右侧已常驻全权控制大纲显隐的「目录大纲」按钮，而大纲侧栏内部右上角仍存在一个面板收起小图标 (`PanelRightClose`)，属于多余控件，应彻底予以清除；
2. **“父子级折叠难道只有一级吗？”——二级标题无法折叠三级小节**：
   - 经逆向穿透数据库真实数据，发现专业长文档中存在大量 `## 一、集合到底是什么？` 与 `## 1.1 集合解决什么问题？` 混合并存的结构；
   - 原系统仅根据 HTML 标签名 (`h1/h2/h3`) 进行机械比对，导致同属 `h2` 的点分编号小节 (`1.1/1.2/1.3`) 被误判为同级兄弟节点，导致 `一、集合到底是什么？` 丧失折叠箭头；
   - 需要建立结合「标签权重 + 文本语义编号层级启发自愈」的智能多层级深度推导体系，使 H1 能折叠 H2/H3，且 H2 亦能精准独立折叠其下属的 1.1/1.2 等小节！

## 二、 1:1 需求物理对账矩阵 (RTM)

| 需求编号 | 需求名称 | 契约重点 |
| :--- | :--- | :--- |
| **REQ-TOC-2.1** | **彻底清除大纲侧栏右上角冗余收起按钮** | 彻底移除大纲内部右上角的 `PanelRightClose` 按钮，由顶栏「目录大纲」按钮统一承担唯一展开/收起职责。 |
| **REQ-TOC-2.2** | **智能多层级深度父子折叠（H1 折叠 H2/H3，H2 独立折叠 H3/小节）** | 引入层级深度启发自愈算法（点分编号 `1.1/2.1` 智能识别为深度 3），使任意包含下属小节的 H1/H2 节点均具备独立的折叠微箭头与折叠徽标，支持任意层级独立折叠收展。 |

## 三、 拟变范围与边界承诺

- 变更文件聚焦在 `src/components/docs/editor/BlockEditor.tsx`。
- 其他组件及数据库数据绝对保持原状与只读。
