# Proposal: 文档编辑功能深度重构——排版所见即所得、Ctrl+Z 历史回退与光标稳定治理

## Why

在文档中心编辑功能的使用中，存在严重的交互缺陷与用户体验断层（用户明确指出：以往审计仅做机械检查，未从真实用户交互角度审查）：
1. **排版功能失效与裸星号残留**: 点击加粗或斜体时，编辑器仅仅在光标处插入 `**` 或 `*` 等原始 Markdown 字符；且在编辑状态下由于采用纯 `<textarea>`，用户看到的永远是充满星号的源码，完全无法实时所见即所得（WYSIWYG），体验支离破碎；
2. **Ctrl+Z 历史撤回完全失效**: 既无法通过 `Ctrl+Z` 撤回输入的文字，也无法撤回排版与块操作；每次敲字直接触发全量 React 重渲染与写库，导致原生文本域撤回缓冲区被彻底销毁；
3. **光标乱跳与失焦跳跃**: 编辑器在“未聚焦预览态 `div`”与“聚焦编辑态 `textarea`”之间频繁销毁重建 DOM，导致光标频繁跳至末尾或丢失选区；每次格式化后焦点丢失；
4. **高频写库性能拖滞与竞态**: 每输入一个字符就发起一次全量异步 SQLite 写库操作，连续打字时大量异步写操作并发竞态，导致偶发吞字、卡顿与保存丢失。

## What Changes

1. **全面升级为原生高保真行内富文本编辑引擎 (Live Inline Rich Editing)**:
   - 彻底废除 `div` 与 `<textarea>` 频繁来回切换销毁的脆弱模式；
   - 采用稳定持久的行内可编辑架构（ContentEditable / Live Preserved Node），所见即所得呈现加粗、斜体、删除线、行内代码与高亮；
   - 选中文本应用加粗时文字直接加粗显示，绝不向用户裸露 `**` 字符；
   - 原生支持 `Ctrl+B`（加粗）、`Ctrl+I`（斜体）、`Ctrl+U` 等主流快捷键。
2. **建立全生命周期撤销/重做历史栈 (Undo/Redo History Engine)**:
   - 在 `BlockEditor` 建立 `undoStack` 与 `redoStack`；
   - 深度捕获 `Ctrl+Z`（撤回）与 `Ctrl+Y` / `Ctrl+Shift+Z`（重做），覆盖文字输入、排版格式应用、块创建、块删除与块类型切换全过程。
3. **光标与选区锁定保全机制 (Caret & Selection Preservation)**:
   - 彻底消灭 DOM 替换带来的光标重置 Bug，光标停留位置与用户点击/输入位置 100% 绝对一致；
   - 应用排版格式后，精准维持原文字选区，绝不跳跃至行尾。
4. **智能输入防抖与用户真实操作链路全维加固**:
   - 引入 500ms 智能防抖持久化（Debounced SQLite Persistence），内存响应 0ms，后台写库平滑安全；
   - 深度加固回车派生新块、退格降级/合并块、Tab 缩进、斜杠 `/` 快速菜单与待办打勾等全部真实操作路径。
