# Proposal: 全局窗口缩小控件防挤压与执行报文控制台页眉重叠修复

## 1. 为什么做 (Why)
用户反馈在窗口缩小或非最大化状态下存在严重的界面挤压与内容异常：
1. **执行报文页眉遮挡/挤压主功能**：当窗口缩小时展开“执行报文”控制台，主工具栏的操作按钮（“+ 新建项”、“执行报文”等）与控制台自身的页眉发生视觉重叠或严重挤压；控制台内部右侧功能按钮（清屏、关闭 X）被推至视口外截断。
2. **启动大盘卡片变形与内容缺失**：启动项网格硬编码了基于全局屏幕宽度的固定列数（`grid-cols-4/5`），在中间容器宽度受限时强行拆分为多列，导致卡片被挤压成几十像素的垂直细长条，文字截断，内容无法正常浏览。
3. **固定侧栏宽度挤占工作区**：分类侧栏固定 256px (`w-64`)，报文控制台固定 380-420px，在紧凑视口下吞噬了绝大部分横向空间，导致核心内容区被极度挤压。

## 2. 核心改动 (What Changes)
- **容器自适应流式网格重构 (Container-Aware Auto-Fill)**：将启动项卡片大盘重构为 `grid-template-columns: repeat(auto-fill, minmax(136px, 1fr))`，确立单卡片人体工学最小安全宽度（136px），彻底杜绝卡片被压扁变形与内容缺失。
- **执行报文页眉紧凑化与防溢出**：重构 `TelemetryPanel.tsx` 顶栏，采用紧凑型过滤标签与图标工具按钮，确保所有控制项（日志等级、自动滚屏、复制、清屏、关闭 X）在任何宽度下均 100% 完整可见，绝对不被截断。
- **顶栏工具区自适应弹性收敛**：优化主工具栏与搜索框弹性伸缩逻辑，彻底消除工具栏与报文面板之间的横向碰撞与遮挡。
- **全局板块比例平衡**：分类侧栏调整为更灵巧舒适的 `w-48 lg:w-56`，报文控制台在紧凑视口下自适应为 `w-[320px] xl:w-[380px]`，为主内容大盘预留充裕的呼吸空间。

## 3. Spec-Kit 需求物理对账矩阵 (RTM 1:1 守恒)
- **REQ-RESP-OVERLAP-01**: 消除主工具栏与执行报文控制台页眉的碰撞与覆盖，保持绝对物理隔离。
- **REQ-RESP-GRID-SQUEEZE-02**: 采用容器自适应流式网格，卡片宽度不低于 136px，彻底解决卡片挤压变形与内容缺失。
- **REQ-RESP-GLOBAL-PANEL-03**: 全局面板自适应弹性排布，报文控制台按钮全量完整呈现，无截断无溢出。
