# Proposal: 快速启动屏幕分屏吸附精度与多窗口去重防重叠加固

## 1. 需求来源与背景 (Background)
用户在快速启动模块使用分屏组合功能（如四分屏启动 MSDS 组合包含 SelfWork、备用版文件夹、源文件材料文件夹、重写版文件夹）时反馈：
1. 各文件/窗口分屏位置落点不准确，存在较大概率有的窗口落在屏幕一（主屏）、有的窗口落在屏幕二（副屏）；
2. 部分窗口重叠在同一个象限槽位，互相遮挡；
3. 需要彻底排查多窗口异步拉起时差、句柄去重互斥与显示器坐标映射机制，确保 100% 准确停靠。

## 2. 1:1 需求物理对账矩阵 (Requirement Traceability Matrix)

| 需求编号 | 需求名称 | 核心规范与验收目标 | 对应任务 |
| :--- | :--- | :--- | :--- |
| **REQ-SNAP-TARGET-01** | 各分屏窗口目标屏幕与象限 100% 精准锚定 | 以目标显示器真实可用工作区坐标为绝对基准，消除窗口跨屏漂移（如主屏副屏混落），保证所有窗口严格落在指定显示器 | Task 1 |
| **REQ-SNAP-DEDUP-02** | 多窗口唯一占位互斥与防重叠机制 | 引入已分配窗口句柄（HWND）黑名单排他池，每个象限槽位 1:1 锁定独立物理窗口，彻底杜绝同一窗口被重复定位或多窗口堆叠 | Task 2 |
| **REQ-SNAP-RETRY-03** | 异步拉起自适应重试与平滑就绪轮询 | 解决多文件夹/应用并发启动时的毫秒级时差问题，在后端建立 3 秒自适应重试轮询管道，确保所有后就绪窗口全部被捕获并精确定位 | Task 2 |
| **REQ-SNAP-AUDIT-04** | 多显示器与分屏全场景自动化测试审计 | 构建包含跨主副屏坐标映射、句柄去重互斥、路径消歧匹配及端到端自动化测试套件，出具真实运行退出码 0 凭据 | Task 3 |

## 3. 拟变范围与不变量约束 (Scope & Invariants)
- **拟变范围**：
  - `src-tauri/src/lib.rs`: 重构 `arrange_combo_windows`，引入循环就绪探测（最大 3.0s 自适应轮询）、已定位 HWND 排他池（Claimed HWND Pool）、精确物理路径消歧匹配与 Win32 `SW_RESTORE` + `SetWindowPos` 状态重置；
  - `src-tauri/src/lib.rs` 中的 `launch_custom_target`: 文件夹启动使用 `/separate` 隔离参数，防止 Windows 11 Explorer 合并为同一窗口的不同标签页；
  - `src/components/LauncherDashboard.tsx`: 优化组合启动调度管道，调整启动各子项与触发分屏编排的等待调度逻辑；
  - `scripts/launcher-snap-tiling-test.mjs`: 编写端到端真实分屏吸附与多屏坐标核销测试套件。
- **保持现状承诺**：
  - 启动项数据结构、SQLite 存储及已保存的组合槽位配置（`WindowLayoutConfig`）绝对保持现状；
  - 文档中心、多维表格与侧边栏绝对保持现状；
  - 其他非分屏启动方式（单项点击、多选顺序启动等）保持现状。
