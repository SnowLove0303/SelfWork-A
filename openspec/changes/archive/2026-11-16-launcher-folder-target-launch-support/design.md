## 2. 核心技术细节与因果拓扑

### 2.1 原生唤起管线优化 (`src-tauri/src/lib.rs`)
- 现有机制中，非 `.exe` 目标均通过 `powershell.exe -Command "Start-Process ..."` 唤起，在打开文件夹时不仅存在 100~300ms 的解释器初始化开销，且偶发前台黑框或路径转义问题。
- 设计针对 `target_path.is_dir()` 引入首要直连通道：
  ```rust
  if target_path.is_dir() {
      // 规范化 Windows 物理路径
      let normalized = trimmed_target.replace('/', "\\");
      let mut cmd = std::process::Command::new("explorer.exe");
      cmd.arg(&normalized);
      cmd.spawn().map_err(|e| format!("唤起资源管理器失败: {}", e))?;
      return Ok(format!("成功打开文件夹: {}", normalized));
  }
  ```
- 若 `target_path` 为明确的物理路径但 `!target_path.exists()`，直接返回明确的中文错误原因，避免操作系统静默抛出难以理解的 Win32 错误码。

### 2.2 前端目录名称提取与防误截断 (`LauncherDashboard.tsx`)
- 当前 `handlePickFile` 中采用 `dotIndex > 0 ? baseName.slice(0, dotIndex) : baseName`，对普通文件能有效剥离扩展名。但若用户选择一个包含版本号或点号的目录（如 `SelfWork.v1` 或 `workspace.antigravity`），原逻辑会将 `.v1` 误判为扩展名而截断。
- 改进设计：当 `isFolder` 为 true 时，直接使用 `baseName` 作为目录推荐名称，杜绝误伤。

### 2.3 异常防御与双清单闭环
- **状态合法性**：路径空白、不存在、无权限状态在 Rust 层与 TS 层双重阻断；
- **组合套件继承**：在 `bundle` 调度中，文件夹项作为独立原子节点被唤起，遵循统一的 150ms 间隔；
- **真实见证**：在 `scripts/launcher-e2e-test.mjs` 中接入文件夹实体与异常目录实测断言，以退出码 0 为充要条件。
