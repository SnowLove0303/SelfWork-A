# Proposal: 快速启动执行报文防挤压与左侧边栏版本信息彻底清除 (Launcher Telemetry Collision Fix & Sidebar Clean)

## 一、 背景与动机 (Why)

用户在日常使用与窗口化缩小时反馈了两处显著破坏使用体验与视觉美感的系统性问题：
1. **执行报文页面在窗口缩小时遮挡/挤压其他核心功能**：
   用户明确指出：> “这个执行报文页面在窗口化缩小时又会挡住 其他功能，这个问题在之前修改过，现在又出现了”
   - 根因诊断：`LauncherDashboard.tsx` 中 `isTelemetryOpen` 默认初始值为 `true`，导致每次进入快速启动大盘时，报文控制台均大面积常驻于右侧；且在布局层作为固定宽度的平级 Flex 子节点（`w-[320px] xl:w-[380px]`），在非全屏、窗口缩小时持续硬性剥夺主视口横向空间，造成顶部操作工具栏（搜索框、多选启动、全启动、+组合、+新建项）严重被挤压碰撞，新建按钮被压扁为单个“+”号，卡片大盘列数骤降。
2. **左下角版本号多余占位与视觉杂音**：
   用户明确指示：> “另外 左下角的版本信息删掉”
   - 根因诊断：`Sidebar.tsx` 最底部包含写死的 `v0.1.0-alpha` 文本与上边框分割线，既无交互用途又破坏了左侧黑色磨砂玻璃质感的极简通透性。

## 二、 1:1 需求物理对账矩阵 (1:1 RTM Ingestion)

严格 1:1 守恒注入 Step 0 确立的两大核心法定需求：

| 需求编号 | 用户原始输入锚点 | 核心业务契约定义 |
| :--- | :--- | :--- |
| **REQ-TELEMETRY-RESPONSIVE-01** | “执行报文页面在窗口化缩小时又会挡住 其他功能，这个问题在之前修改过，现在又出现了” | 执行报文控制台默认为轻量收起状态（`isTelemetryOpen = false`），将完整视口全量留给启动卡片与工具栏；展开时采用右侧优雅悬浮抽屉（Overlay Drawer）或自适应无损定位模式呈现，彻底杜绝主工具栏按钮受挤压截断变形与卡片列数崩塌，随时可一键呼出与一键关闭（X）。 |
| **REQ-SIDEBAR-PURGE-VERSION-02** | “另外 左下角的版本信息删掉” | 彻底清除左侧导航栏底部的 `v0.1.0-alpha` 标签容器及关联的横向分割线，底部空间恢复纯净通透，杜绝多余占位。 |

## 三、 法定双清单 (Dual-List Precondition)

### 1. 拟变范围清单 (Proposed Scope)
- `src/components/LauncherDashboard.tsx` `[State Transition / UI]`:
  - 将 `isTelemetryOpen` 初始默认值调整为 `false`；
  - 重构报文控制台呈现模式为优雅右侧悬浮抽屉（`absolute right-0 top-0 bottom-0 z-30`），具备背景磨砂高斯模糊与深邃投影，打开时零挤压中间主工具栏和网格卡片，关闭时零空间占用；
- `src/components/Sidebar.tsx` `[UI / Visual Parity]`:
  - 彻底移除底部包含 `v0.1.0-alpha` 的 `div` 容器与 `border-t` 分割线；
- `CHANGELOG.md` `[Knowledge Persistence]`:
  - 登记版本演进、5-Whys 根因与防反复下沉记录。

### 2. 保持现状承诺清单 (Preservation Commitments)
- ✅ **侧栏几何承重墙**：左侧主导航栏 `w-48`（或折叠态）宽度与 `h-[49px]` 顶栏基准线绝对对齐不变；
- ✅ **报文功能契约完整性**：`TelemetryPanel.tsx` 内部的全部功能（日志过滤、自动滚屏、复制全部、清空报文、关闭按钮）逻辑与状态 100% 保持完好；
- ✅ **调度内核与数据无损**：Rust 原生调度命令、脚本执行通道及 SQLite 中用户所有应用和分类数据 100% 不受影响。
