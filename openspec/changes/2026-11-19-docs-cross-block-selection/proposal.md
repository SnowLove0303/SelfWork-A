# 变更提案：文档跨块无缝自然划选与批量协同系统 (Proposal)

## 一、 需求溯源与问题根因

用户反馈在长文档中进行大段内容选择时：
> `去排一个问题： 无法跨块选中内容`
> `我希望能够像word 一样自然选中大片内容，而不是被阻断`

### 终极底层根因透穿
1. **输入框孤岛阻断机制**：在原架构中，每一个块无论是否正在输入，均声明为独立的 `contentEditable={true}`。在浏览器（Chromium/WebKit）底层规范中，每个 `contentEditable` 元素等同于一个独立的编辑宿主（Editing Host，类似于独立的 `<textarea>`）。浏览器原生安全与排版规范严禁用户的鼠标文字划选手势跨越两个不同的编辑宿主边界，导致鼠标一旦滑出当前块，选区立刻被截断；
2. **缺乏跨块连续手势协同器**：当鼠标跨越块边界时，编辑器未接管拖拽手势，亦未建立跨块虚拟选区范围（`Cross-Block Selection Range`），导致用户无法像在 Word 或普通网页中一样连续划选多段、多个列表项或大章节。

## 二、 1:1 需求物理对账矩阵 (RTM 继承)

| 需求编号 | 需求名称 | 契约重点 |
| :--- | :--- | :--- |
| **REQ-CROSS.1** | **Word 级自然无阻断跨块鼠标拖选** | 建立跨块选区协同器（`CrossBlockSelectionCoordinator`），当鼠标在某块按下并拖拽跨出块边界时，平滑捕获起始块至终止块的所有块节点，呈现与 Word 毫无二致的连续连贯选中高亮。 |
| **REQ-CROSS.2** | **跨块选中内容的完整复制 (`Ctrl+C`)** | 跨块选中生效时，全局捕获 `copy` 事件，按顺序将跨选范围内的所有块内容合并拼接换行符写入剪贴板，外部粘贴时段落结构 1:1 完整无损。 |
| **REQ-CROSS.3** | **跨块选中内容的批量删除与打字替换** | 跨块选中时按下 `Backspace` / `Delete` 批量销毁选中块，首尾块剩余内容平滑接合；若直接键入文字，先清除选中范围再插入新文本。 |
| **REQ-CROSS.4** | **单块编辑与跨块划选无缝解耦** | 单块内点击输入、双击选词、三击选行保持原有原生极速打字与 Markdown 解析体验不变，仅在发生跨块拖拽时无缝激活跨块选区。 |

## 三、 拟变范围与影响半径

- 变更文件聚焦在：
  - `src/components/docs/editor/BlockEditor.tsx`：挂载跨块鼠标手势协同器、跨块选区状态管理、全局复制与删除快捷键接管；
  - `src/components/docs/editor/BlockItem.tsx`：支持接收跨块选中高亮属性 (`isCrossSelected`)，提供跨块状态视觉覆盖与光标失焦自愈。
- 数据库层与系统后端（Rust 单元测试 14/14）绝对保持只读。
