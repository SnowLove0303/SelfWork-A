# Proposal: Docs Advanced Table Editing Engine

## 1. 提案背景与问题陈述 (Context & Problem Statement)

在之前的版本迭代中，文档系统的表格块（`TableBlock.tsx`）具备了基础的双向渲染、列宽鼠标拖拽调整（`columnWidths`）、首行表头高亮切换、末尾追加行列及复制 Markdown 的能力。
然而，随着用户对高效率文档编写、结构化数据录入和专业排版的需求升级，当前的表格编辑能力暴露了以下局限：
1. **行列插入受限**：只能在末尾“追加”新行新列，无法在表格中间的任意光标位置向上/向下插入行，或向左/向右插入列；
2. **缺乏列对齐控制**：所有列默认左对齐，无法针对数值列、状态列或代码列设置“居中”或“右对齐”，且导出 Markdown 时无法生成符合 GFM 规范的 `:---:` 对齐符号；
3. **键盘录入不畅**：在单元格内按回车时行为单一，缺乏“回车跳至同列下一行（自动录入表格）”与“`Shift + Enter` 单元格内换行”的高效人机工程支持；
4. **缺少精准单元格/行列操作上下文**：无法一键清空某行某列，缺少基于当前光标焦点的快捷操作栏。

## 2. 变更目标与 1:1 需求对账矩阵 (Requirements Traceability Matrix)

| 需求项 ID | 用户原始需求 (Spec-Kit 1:1 摄入) | 变更目标与技术落地 | 验证标准 (Acceptance Criteria) |
|---|---|---|---|
| **REQ-1** | 任意位置插入行与插入列 | 提供 `insertRow(rIdx, 'above' \| 'below')` 与 `insertCol(cIdx, 'left' \| 'right')`。在表头单元格与行操作区提供直观的微按钮与快捷操作栏 | 在任意行/列触发插入，新行/列精准出现在指定位置，现有列宽与对齐数组正确顺延 |
| **REQ-2** | 整列对齐方式调节 (左/中/右) | 增加 `properties.columnAlignments` 属性（`'left' \| 'center' \| 'right'`），在表头提供快速对齐切换胶囊；并在复制/导出 Markdown 时输出标准 `:---:` 分割线 | 切换对齐后界面单元格文本即时响应对齐；导出的 Markdown 在外部工具中精确呈现居中/右对齐 |
| **REQ-3** | 单元格键盘流深度增强 | 拦截 `Enter` 与 `Shift+Enter`：回车直接下移并聚焦同列下一行（在最后一行回车自动加行）；`Shift+Enter` 在单元格内部换行；`Tab` / `Shift+Tab` 左右循环跳格 | 双手不离键盘即可完成连续表格录入，与 Excel / Notion 键盘手感完全一致 |
| **REQ-4** | 行列快捷操作浮条与清空功能 | 聚焦单元格时提供轻量快捷操作浮条：支持快速复制当前行/列数据为制表符分隔文本、清空整行/整列内容（保留空单元格结构） | 浮条响应灵敏且不遮挡文字输入，清空操作即时更新且支持撤销 |

## 3. 架构影响与风险评估 (Impact Analysis)

1. **对既有数据格式的兼容性**：
   - 存量数据若未包含 `columnAlignments`，自动缺省回退为 `'left'`，100% 向后兼容；
   - `columnWidths` 保持与现有拖拽调整系统完全解耦并协同；
2. **对已有功能的不变量承诺**：
   - 表格自愈引擎 `healTableRows` 与竖线转义保护 100% 保持生效；
   - 字符级选区、快捷复制、导出物理文件等能力 100% 保持稳定。
