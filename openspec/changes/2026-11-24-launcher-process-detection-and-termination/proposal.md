# Proposal: 快速启动模块纳入项进程检测与终止管理 (Launcher Process Detection and Termination)

## 1. 业务背景与用户意图

当前 SelfWork 快速启动模块已实现丰富的单品启动、批处理分屏组合启动（Bundle Suites）及可执行文件图标提取。但在日常桌面使用中，用户在启动各应用后无法获知哪些应用正处于运行状态，也无法在启动台内直接关闭不需要的程序。

用户提出明确诉求：
> “快速启动模块 要计划开发一个 检测所有纳入快速启动项的项的进程检测和关闭功能，你计划一下，只对纳入启动项的做进程检测和关闭，以及需要考虑UI 该功能的位置和编排，要不就已有启动项的图标右上角做进程检测，在运行的支持关闭，包括组合启动项（不要影响可重复的进程启动）”

## 2. 1:1 需求物理对账矩阵 (RTM)

- **REQ-1 (纳入项专属性范围)**: 严格只针对已纳入快速启动列表的单项或组合项执行运行检测与关闭，不越界漫游扫描或误干预系统全局无关进程；
- **REQ-2 (图标右上角感知与一键关闭)**: 在启动项卡片/图标的右上角呈现精致低扰动的运行状态角标（常驻微绿发光圆点）；当检测到运行中时，鼠标悬停右上角浮现“✕”微关闭按钮，点击或右键菜单直接一键终止进程；同时点击卡片主体仍执行正常启动/前台唤起；
- **REQ-3 (组合启动项复合感知与联动关闭)**: 组合启动项联动检测所包含的全部子项运行状态（全运行为翡翠绿、部分运行为琥珀黄）；支持在组合卡片上一键批量关闭所有子项进程，或在子项微缩胶囊中单项关闭；
- **REQ-4 (多实例与可重复启动保障)**: 即使项已被检测为运行中，用户点击卡片仍能正常发起重复启动（多开窗口）；多实例项在关闭时受控清理所有对应实例；
- **REQ-5 (极简 UI 编排与双轨交互)**: 采用极简微视觉设计，未运行时无多余视觉噪音；右键菜单同步增设“🔴 结束运行 (Kill)”选项，形成角标悬停与右键菜单双轨闭环。
