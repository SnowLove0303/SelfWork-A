# Proposal: 快速启动重构为通用灵活的跨设备桌面启动工作台

## 1. 提案背景与事实指纹溯源
- **原始需求指纹**:
  > “关于快速启动模块，我先做调整，考虑到后续该工作台的跨设备通用型问题，我觉得还是不要跟wll做绑定了，先去掉wll这个重新做吧，我的计划是 允许输入指定路径和名称设置快速启动项，允许这个添加或删除快速启动项，允许设置分类，允许捆绑启动，允许设置快速允许脚本之类的，总计就是我想要从操作层面上达到通用性和灵活性，明白我意思？”
- **根本痛点分析**:
  - 当前快速启动模块深度硬编码了原环境专属的 WSL 脚本与固定端口探查（`Workflow-Launcher.ps1` 与固化集群列表），在其它机器或新设备上无法开箱即用，缺失通用性；
  - 缺乏面向终端用户的纯前端动态配置与 CRUD 能力，无法自由增加本地 `.exe`、文件夹、URL 或个性化脚本。
- **重构目标**:
  - 全面解耦原硬编码 WSL 与固定端口探测逻辑，转向以数据模型驱动的“通用跨设备桌面启动引擎”；
  - 赋能用户在 UI 界面中对启动项（路径/名称/类型/参数）进行增删改查；
  - 引入自由分类（Categories）管理与按分类一键“捆绑全启动”能力；
  - 引入命令行脚本快捷运行器（PowerShell / CMD 指令直接运行与结果反馈）；
  - 全量配置通过 SQLite / 本地数据库持久化落盘，开箱即用、跨设备通用。

## 2. 1:1 需求物理对账矩阵 (RTM)

| 需求编号 | Spec-Kit 需求条目 | 拟定解决方案与边界 | 验收充要条件 |
| :--- | :--- | :--- | :--- |
| `REQ-LAUNCHER-01` | 解耦特定环境与 WSL 硬编码绑定 | 移除原硬编码脚本依赖，构建跨平台的 Rust 动态启动与执行 IPC 接口。 | 跨机器开箱即用，无任何硬编码路径依赖报错。 |
| `REQ-LAUNCHER-02` | 自定义快速启动项录入与增删改查 (CRUD) | 在 UI 建立启动项动态管理弹窗与卡片，支持名称、目标路径、类型、参数自由录入与编辑/删除。 | 可以在界面上添加任意本地程序/网页/目录，点击直接调用拉起。 |
| `REQ-LAUNCHER-03` | 自由分类管理体系 | 支持创建、重命名、删除分类组，启动项灵活分配归属，多分类流畅切换筛选。 | 支持多分类分组整理，徽标实时统计各分类项数。 |
| `REQ-LAUNCHER-04` | 一键分类捆绑全启动 (Bundled Launch) | 分类工具栏提供“一键全启动”按键，并发/平滑拉起当前分类下所有目标应用或脚本。 | 一键拉起分类内全部项目，提升批量工作流效率。 |
| `REQ-LAUNCHER-05` | 快速运行脚本支持 (Script Runner) | 支持配置为“命令行脚本”类型（PowerShell/CMD），点击直接调用后台静默或终端执行，反馈执行结果。 | 可自由录入 CLI 命令并一键运行，输出清晰执行状态。 |
| `REQ-LAUNCHER-06` | 本地持久化与架构承重墙 100% 保护 | 配置持久化至 SQLite 数据库；全局 `Sidebar.tsx` / `Titlebar.tsx` 0 行修改；顶栏基准高度 `h-[49px]` 绝对守恒。 | 重启应用数据完整恢复；待办与导图模块零受损，切页平齐。 |
